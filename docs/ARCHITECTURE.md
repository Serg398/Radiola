# Структура приложения

Приложение остаётся одним Gradle-модулем. Разделение пакетов определяет роли
компонентов; JNI-классы и Android entry points сохраняют прежние полные имена.

| Пакет | Ответственность |
| --- | --- |
| `receiver` | Общие модели, интерфейс онлайн-сессии, команды экрана и история FFT |
| `sources.usb` | Владение USB-устройством, последовательность аппаратных команд |
| `sources.websdr` | Протокол WebSDR, его диапазоны, каталог и потоки |
| `sources.openwebrx` | Протокол OpenWebRX, профили, режимы и декодирование потока |
| `sources` | Владение онлайн-сессиями на уровне приложения |
| `audio` | AudioTrack, очереди, восстановление звука, шумодав и синхронизация PCM |
| `decoders.cw`, `decoders.ftx` | Декодеры и фоновые задачи CW/FT |
| `ui.receiver` | Экран, ViewModel, частота, спектр, водопад, S-метр, энкодер |
| `ui.components` | Повторно используемые кнопки и элементы панели |
| `ui.decoders`, `ui.map`, `ui.settings`, `ui.theme` | Карточки, карта, настройки и оформление |
| `platform` | Разрешения, геолокация, вибрация, настройки и уведомления |
| `telemetry` | Замеры времени обработки и отрисовки |

## Владение и поток команд

`RadiolaApplication` владеет USB runtime и runtime онлайн-источников. Они живут
дольше Activity и ViewModel: пересоздание экрана не должно закрывать поток.
Android-сервисы обеспечивают фоновое воспроизведение.

`ReceiverViewModel` выполняет команды USB и сохраняет состояние ввода.
Его `ReceiverPresentation` выбирает получателя команд, формирует `ReceiverUiState`
и собирает состояние декодеров в `viewModelScope`. Выбранный FT-режим сохраняется
через `SavedStateHandle`. Компоненты частоты, спектра и S-метра получают данные
и обработчики и не создают сессии.

`OnlineReceiverSession` использует общие модели источника, соединения, диапазона,
режима и аудиометрик. Он предоставляет операции декодирования, не открывая UI
конкретные worker-классы. Настройки источника сериализуются прежними строками:
`USB`, `WebSDR`, `OpenWebRX`; существующие SharedPreferences совместимы.

`OpenWebRxStreamDecoder` хранит состояние формата потока для одного WebSocket.
Сессия отвечает за соединение и восстановление, декодер — за конфигурацию
кодеков, PCM, FFT и перевод уровня сигнала. WebSDR сохраняет отдельную реализацию
протокола. Общий интерфейс не означает общий формат сетевого обмена.

FT-карточка получает источник и адрес сервера явно. Отрисовка строк отделена
от загрузки стран, определения координат и подготовки контактов.

## Ограничения переноса

`NativeSdr`, `NativeFtx`, `SpectrumFrame`, `RdsFrame` остаются в
`com.example.sdr`: JNI использует эти имена. Сгенерированный `DemodulationMode`
также сохраняет прежний пакет. DSP и аудиобуферы не перестраиваются ради UI.

## Проверка изменений

Автоматические проверки: JVM-тесты, сборка приложения и instrumented APK,
`ReceiverPresentationTest`, `ReceiverLifecycleTest`, `WebSdrLifecycleTest`,
`OpenWebRxSessionTest`, `FtxNativeTest`. Сетевые lifecycle-тесты используют
локальные MockWebServer; тесты публичных серверов требуют явного адреса.

Ручная проверка: источник и запуск/остановка; настройка каждой цифры частоты
и округление; MODE/BW/BAND; SQL; свайп и масштаб водопада; CW и FT;
RADIO/MAP; обе темы; сворачивание и восстановление приложения. USB с реальным
эфиром и публичные серверы проверяются отдельно от локальных сетевых тестов.
