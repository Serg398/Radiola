# Выпуск Радиолы

## Версии

Единственный источник номера версии — `version.properties` в корне проекта.
`versionName` имеет формат MAJOR.MINOR.PATCH, например 0.2.0 или 0.3.0-beta.1.
PATCH — исправления, MINOR — функции, MAJOR — крупные изменения.
`versionCode` увеличивается для каждого нового распространяемого APK, включая beta.
Обычная локальная пересборка не требует изменения версии.

Debug имеет applicationId `com.serg398.radiola.debug` и название «Радиола Dev».
Release имеет applicationId `com.serg398.radiola`. После публикации его не менять.
Данные debug и release независимы. Ранее установленная debug-сборка без суффикса
может конфликтовать с release из-за другого сертификата подписи.

## Подпись

Создать постоянный ключ выпуска через Android Studio: Build → Generate Signed
App Bundle or APK → APK → Create new. Хранить ключ вне репозитория, сделать
резервную копию ключа и паролей. Для всех обновлений использовать тот же ключ.

Скопировать `keystore.properties.example` в `keystore.properties`, заполнить
путь, alias и пароли. Файл исключён из Git. В путях использовать `/`.
Для CI вместо файла доступны переменные окружения (имеют приоритет):
`RADIOLA_STORE_FILE`, `RADIOLA_STORE_PASSWORD`, `RADIOLA_KEY_ALIAS`,
`RADIOLA_KEY_PASSWORD`. Не передавать пароли в аргументах команд.
Без полной конфигурации подписи упаковка release завершается ошибкой.

На текущем рабочем компьютере ключ создан в `%USERPROFILE%/.radiola/release.jks`,
а копия параметров подписи — в `%USERPROFILE%/.radiola/keystore.properties`.
Доступ ограничен текущим пользователем и SYSTEM. Рабочий файл параметров также
находится в корне проекта и исключён из Git. Ключ и файл параметров нужно
скопировать в защищённое резервное хранилище: копия на том же диске не является
резервной копией. Не публиковать эти файлы вместе с APK.

## Проверка и публикация

1. Убедиться, что рабочее дерево содержит только изменения выпуска.
2. Обновить version.properties и CHANGELOG.md, указать дату выпуска.
3. Использовать JDK Android Studio; версии Gradle, NDK и JVM закреплены в проекте.
4. Выполнить из корня:

   ```powershell
   .\gradlew.bat :app:testDebugUnitTest :app:assembleRelease
   ```

5. APK: `app/build/outputs/apk/release/app-release.apk`. Проверить подпись
   через `apksigner verify --verbose --print-certs` из SDK build-tools.
6. Установить именно этот APK на телефон. Проверить обновление поверх предыдущего
   release с сохранением настроек и избранного, USB, оба онлайн-источника,
   фон, затронутые декодеры. При изменениях DSP запустить scripts/Run-DspTests.ps1;
   Android-тесты требуют подключённого устройства.
7. Зафиксировать изменения. Создать аннотированный тег `v0.2.0` на проверенном
   коммите; имя тега должно совпадать с versionName. Отправка тега и публикация
   выполняются отдельно, когда выпуск готов.
8. Опубликовать проверенный APK под именем `radiola-0.2.0.apk`, описание изменений
   и SHA-256 (`Get-FileHash <путь-к-APK> -Algorithm SHA256`). Сохранить исходный APK,
   Git-коммит, versionCode, отпечаток сертификата и контрольные суммы моделей.

Тег и опубликованный APK не заменять. Исправления выпускать новой версией.
Для Google Play собирать `:app:bundleRelease`; AAB не предназначен для прямой
установки с сайта. Автоматизация CI пока не настроена.
