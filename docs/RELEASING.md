# Выпуск Радиолы

## Версии

Единственный источник номера версии — `version.properties` в корне проекта.
`versionName` имеет формат MAJOR.MINOR.PATCH, например 0.2.0 или 0.3.0-beta.1.
PATCH — исправления, MINOR — функции, MAJOR — крупные изменения.
`versionCode` увеличивается для каждого нового распространяемого APK, включая beta.
Обычная локальная пересборка не требует изменения версии.

Debug имеет applicationId `com.serg398.radiola.debug` и название «Радиола Dev».
Release имеет applicationId `com.serg398.radiola`. После публикации его не менять.
Данные debug и release независимы. Ранее установленная debug-сборка без суффикса
может конфликтовать с release из-за другого сертификата подписи.

Release использует R8 и удаление неиспользуемых ресурсов. Правила в
`app/proguard-rules.pro` сохраняют JNI-имена, конструкторы нативных снимков,
ONNX и отражение встроенных объектов Rhino. Настольные GUI-инструменты Rhino
не должны попадать в Android APK. Нельзя заменять эти правила общим подавлением
предупреждений R8 или удалять их ради нескольких килобайт.

Для проверки оптимизированного кода без замены установленного приложения:

```powershell
.\gradlew.bat :app:assembleVerification
.\gradlew.bat :app:assembleVerificationAndroidTest '-Pradiola.testBuildType=verification'
adb install -r app/build/outputs/apk/verification/app-verification.apk
adb install -r app/build/outputs/apk/androidTest/verification/app-verification-androidTest.apk
adb shell am instrument -w com.serg398.radiola.verification.test/com.example.sdr.ReleaseSmokeInstrumentation
```

`verification` наследует release, подписывается debug-ключом и имеет отдельный
applicationId `com.serg398.radiola.verification`. Это временная тестовая сборка,
её нельзя публиковать как release. Проверить JNI, FT8, ONNX-декодеры и JS-плагины
на устройстве; синтетические JNI-векторы под `#ifndef NDEBUG` в ней отсутствуют,
поэтому для FT8 используется тест реальной записи.
Проверка использует собственный Android Instrumentation без зависимости от ABI
AndroidX Test и оптимизируемых Kotlin-фасадов. Успех: `status=passed`, `checks=6`.
Обычные UI/lifecycle-тесты запускаются на debug стандартным AndroidJUnitRunner.

## Подпись

Для обновления уже установленной «Радиолы» использовать существующий ключ
выпуска. Если его нет на компьютере, восстановить из резервной копии.
Хранить ключ вне репозитория и сохранять резервную копию ключа и паролей.

Скопировать `keystore.properties.example` в `keystore.properties`, заполнить
путь, alias и пароли. Файл исключён из Git. В путях использовать `/`.
Для CI вместо файла доступны переменные окружения (имеют приоритет):
`RADIOLA_STORE_FILE`, `RADIOLA_STORE_PASSWORD`, `RADIOLA_KEY_ALIAS`,
`RADIOLA_KEY_PASSWORD`. Не передавать пароли в аргументах команд.
Без полной конфигурации подписи упаковка release завершается ошибкой.

Для первого публичного выпуска 0.2.1 создан постоянный ключ RSA 4096
в `%USERPROFILE%/.radiola/release.jks` (контейнер PKCS#12, alias `radiola`).
Параметры подписи хранятся в `%USERPROFILE%/.radiola/keystore.properties`.
Открытый отпечаток нового сертификата закреплён в скрипте сборки выпуска.
Ключ и параметры подписи следует сохранить в отдельном защищённом хранилище
до публикации. Локальные копии на одном диске не заменяют резервную копию.

Предварительная сборка 0.2.0 на тестовом телефоне подписана другим ключом.
Android отклонит обновление поверх неё. Для проверки 0.2.1 нужна чистая
установка на свободное устройство либо удаление прежней версии с потерей её данных.

## Проверка и публикация

1. Убедиться, что рабочее дерево содержит только изменения выпуска.
2. Обновить version.properties и CHANGELOG.md, указать дату выпуска.
3. Использовать JDK Android Studio; версии Gradle, NDK и JVM закреплены в проекте.
4. Выполнить из корня:

   ```powershell
   .\scripts\Build-Release.ps1
   ```

5. Скрипт запускает unit-тесты и Lint, собирает APK, сверяет подпись,
   идентификатор и версию. Готовые файлы находятся в
   `app/build/distributions/radiola-<версия>/` вместе с SHA-256 и отчётом подписи.
   В каталоге также сохраняется `mapping.txt`. Хранить его вместе с конкретным
   APK: карта другой пересборки не подходит для расшифровки стеков R8.
6. Установить именно этот APK на телефон. Для последующих выпусков проверить
   обновление поверх предыдущего APK с тем же ключом и сохранение настроек
   и избранного. Проверить USB, оба онлайн-источника,
   фон, затронутые декодеры. При изменениях DSP запустить scripts/Run-DspTests.ps1;
   Android-тесты требуют подключённого устройства.
7. Зафиксировать изменения. Создать аннотированный тег `v<версия>` на проверенном
   коммите; имя тега должно совпадать с versionName. Отправка тега и публикация
   выполняются отдельно, когда выпуск готов.
8. Опубликовать проверенный APK под именем `radiola-<версия>.apk`, описание изменений
   и SHA-256 (`Get-FileHash <путь-к-APK> -Algorithm SHA256`). Сохранить исходный APK,
   Git-коммит, versionCode, отпечаток сертификата и контрольные суммы моделей.

Тег и опубликованный APK не заменять. Исправления выпускать новой версией.
Для Google Play собирать `:app:bundleRelease`; AAB не предназначен для прямой
установки с сайта. Автоматизация CI пока не настроена.
